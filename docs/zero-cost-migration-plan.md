# 無料クレジット切れ後の移行計画（無料でほぼ同じ運用を続けるには）

2026-08-19 調査。料金・無料枠・規約はすべて当日時点の公式ページで確認した
（重要な8項目は別担当が原典に当たって再検証済み）。無料枠は予告なく変わるため、
着手直前に「出典」のページを再確認すること。

## 結論（先に要点）

- **移行の締切は2026年9月29日ごろ**（残クレジット$114.08 ÷ 実測$2.85/日 = 約40日）。
  アカウント期限の2027-01-26より先にクレジットが尽きる。
  当初「10月上旬〜中旬」と見ていたが、日次実績を見ると消費は月$85ペースで、
  想定より速かった。残り日数は `./scripts/check-credits.sh` で随時確認できる。
- 費用の93%は「置き場所」代で、**AI自体は月$5（約800円）しか使っていない**。
  置き場所はすべて無料枠に移せる実測サイズだった（DB 60MB、PDF 416MB、質問4〜27件/日）。
- **無料でほぼ同じ運用は可能。ただし妥協点が4つ**（回答品質・朝イチの起動待ち・
  PDF表示の遅延・データの保存先が海外になる）。詳細は後述。
- 推奨は **案A（カード登録を一切しない構成）**。カード1枚を許容できるなら
  **案B（Cloud Run 東京）** の方が体感がよい。
- 認証をCognitoから**会社のMicrosoft 365（Entra ID）**に替えると、
  招待メール・SESの迷惑メール問題・ユーザー管理が丸ごと不要になる。
  これはどの案でも共通して推奨。

## 締切の根拠（実測）

| 項目 | 値 | 確認方法 |
| --- | --- | --- |
| 残りクレジット | $114.08 | `aws freetier get-account-plan-state` |
| 1日あたりの消費 | $2.67〜$3.79（14日連続で計測、平均$2.85） | Cost Explorer 日次 |
| 月あたり | 約$85 | 上記×30 |
| 枯渇見込み | **2026年9月29日ごろ**（残り約40日） | 上記から算出 |
| アカウント期限 | 2027-01-26 | 同API |

この数字は `./scripts/check-credits.sh` で再計算できる（週1回は見ること）。

クレジットが尽きる（または期限到達）と**アカウントは自動閉鎖**され、
リソースは止まり、データは**90日後に完全削除**される。
90日以内に有料プランへ上げれば復旧できるが、それは「課金する」ことに他ならない。
出典: https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html

**AWSに残る道はない**ことも確認済み:
- 常時無料枠に RDS / Fargate / ALB は含まれない（現構成の3本柱すべて対象外）
- 法人で別の無料アカウントを作り直すのは規約違反
  （新規顧客限定・entity単位1回。発覚すると特典没収）
  出典: https://aws.amazon.com/free/terms/

### 締切を延ばす手（必要なら）

`scripts/aws-stop.sh` で夜間・休日に止める。実測の内訳から見積もると、
止まらない固定費（ALB・パブリックIP・Secrets Manager）が約$1.20/日、
止められる分（ECS・RDS・Bedrock）が約$1.93/日。平日日中だけの稼働にすると
合計約$1.78/日まで下がり、**残りは約64日（11月上旬まで）** に伸びる。

引き換えに、夜間・休日は現場からマニュアルを見られなくなる。
移行作業が締切に押されるようなら使う保険として持っておく。

## 部品ごとの移行先（調査結果）

### データベース（PostgreSQL + pgvector）

| 候補 | 無料枠 | 東京 | カード | 難点 |
| --- | --- | --- | --- | --- |
| **Supabase Free** ← 推奨 | 500MB・pgvector対応 | **あり** | 不要 | **1週間アクセスが無いと一時停止**（手動復帰。年末年始に注意） |
| Neon Free | 0.5GB・100CU時間/月 | なし（シンガポール） | 不要 | 5分でサスペンド（復帰は数百ms） |
| Prisma Postgres | 500MB | あり | 不要 | 月10万クエリ上限が不安（当時は30名利用の想定。実際は登録8名・利用2〜3名） |

- Supabaseの一時停止は「1日数回のDBアクセスが1週間続けば回避できる」と公式に明記。
  GitHub Actionsの定期ping（無料）で恒久回避できる。復帰APIもある。
  出典: https://supabase.com/docs/guides/platform/free-project-pausing
- pgvector 1024次元・HNSWはどちらも対応（Neonは2,000次元まで対応と明記）。

### PDF・添付画像の置き場所（S3互換）

| 候補 | 無料枠 | カード | 難点 |
| --- | --- | --- | --- |
| **Backblaze B2** ← 案A | 10GB・ダウンロード月3倍まで無料 | **不要**（公式明記） | 日本リージョンなし（米国西海岸。表示に+0.1〜0.2秒） |
| Cloudflare R2 ← 案B | 10GB・転送量無料・APAC配置可 | **必要**（有効化に決済登録） | カードが要る点のみ |

- どちらもS3互換API・presigned URL対応。コードはエンドポイント差し替えのみ
  （ローカルのMinIOと同じ仕組み。`S3_ENDPOINT` を変えるだけ）。
- どちらも「ブラウザからのフォームPOSTアップロード」は非対応だが、
  本アプリはpresigned PUT方式なので影響なし。

### アプリ本体（NestJS + FastAPI の2コンテナ）

| 候補 | 無料枠 | 東京 | カード | 難点 |
| --- | --- | --- | --- | --- |
| **Render Free** ← 案A | 750時間/月（全サービス合算） | なし（シンガポール） | **不要**（公式明記） | 15分無通信でスリープ→**復帰に約1分**。512MB RAM |
| **Cloud Run** ← 案B | 月200万リクエスト・vCPU 18万秒 | **あり** | **必要**（課金アカウント必須） | 完全0円の保証はない（超過は自動課金。本規模なら実質$0） |
| Koyeb / Fly / HF Spaces | — | — | — | 2026年時点で全滅（1個限定・無料廃止・Docker有料化） |

- Renderの750時間は2サービス合算。スリープ前提なら余るが、営業時間中
  （平日8-18時）だけ定期pingで起こしておく運用でも 2×約220時間=440時間で収まる。
  → 朝イチの1回だけ約1分待ち、日中は待ちなし、が現実的な落とし所。
- フロントは**Cloudflare Pages**（無料・カード不要）で配信。

### AIの回答生成・埋め込み・画像理解 ← ここが一番重要な調査結果

社内文書を扱うため「**無料枠の入力が学習に使われるか**」を規約原文で確認した。

| 候補 | 学習利用 | 無料枠 | vision | カード |
| --- | --- | --- | --- | --- |
| **Cloudflare Workers AI** ← 推奨 | **使わない**（公式明記） | 10,000ニューロン/日 ≒ 本アプリの負荷で**約80質問/日** | あり（Llama 3.2 11B） | **不要** |
| Groq | **使わない**（規約§4.2、ZDR設定可） | 数値非公開（コンソール内。第三者情報では70Bが日100Kトークン=約15問で不足の恐れ） | 主力モデルがテキストのみに | 不明 |
| Gemini API 無料枠 | **使う**。人間レビューあり。規約に「機密情報を送るな」と明記 | 大きい | あり | 不要 |
| Mistral 無料枠 | 既定で使う（オプトアウト可否は未確認） | 非公開 | — | 不要 |
| OpenRouter :free | プロバイダ依存（学習拒否設定だと使えるモデル激減） | 50回/日 | — | 不要 |

- **Gemini無料枠は容量・日本語品質では最有力だが、規約上この用途に使ってはいけない。**
  「送信内容を製品改善に使う」「機密・秘密情報をUnpaid Servicesに送信しないこと」
  と明記されている（2026-04-28版で確認）。
  出典: https://ai.google.dev/gemini-api/terms
- Workers AIは学習に使わないことを明記し、埋め込み（bge-m3）まで揃う。
  出典: https://developers.cloudflare.com/workers-ai/platform/pricing/
- **bge-m3は1024次元 = 今のTitan V2と同じ**。pgvectorの列定義はそのまま使える。
  ただし埋め込み空間が違うので全チャンクの再埋め込みは必要
  （3,207チャンク×約330字 ≒ 無料枠1日分の3割で完了。一晩で終わる）。
  再埋め込みは**保存済みのチャンク本文**から行うので、スキャンPDFの
  書き起こしをやり直す必要はない。

### 認証とメール → 会社のMicrosoft 365で置き換え（追加費用ゼロ）

検証済み: M365 Business系ライセンスに含まれるEntra ID Freeで、
SPA+APIのアプリ登録と社内ユーザーのOIDCサインインは追加費用なしで使える。
出典: https://learn.microsoft.com/en-us/entra/fundamentals/licensing

| 今 | 移行後 | 消える問題 |
| --- | --- | --- |
| Cognito（招待制・仮パスワード） | 社員が**会社のMicrosoftアカウントでそのまま入る** | 招待メール、仮パスワード、パスワード移行（不要になる）、ユーザー管理画面の大半 |
| SES（迷惑メール対策に苦労中） | **Graph APIで共有メールボックスから送信**（30通/分まで） | SES本番申請、DKIM設定、迷惑メール問題そのもの |

必要なのは会社のIT管理者への依頼2件:
アプリ登録（Application Developerロール以上）と、Mail.Sendアプリ権限への
管理者同意（+送信元を共有メールボックスに限定するRBAC設定）。

### 検討して外した案

- **Oracle Cloud Always Free**（VM 1台に全部載せる案）:
  2026年6月に無料枠が**告知なしで半減**（4 OCPU/24GB→2/12GB）、東京は容量不足で
  作成失敗が頻発、7日アイドルで回収の規定、突然のアカウント停止事例あり、カード必須。
  業務システムの土台には不適と判断。
- **会社にミニPCを置くセルフホスト**: 機密性は最強だが、
  (1) LLMだけは結局外部API（N100級で動くのは3Bクラスで品質が大幅に落ちる）、
  (2) 外部公開にはCloudflare Tunnelが要り、会社ドメインのネームサーバー移管
  （大ごと）か別ドメイン取得（年約1,000円）が必要、
  (3) ハード代・電気代・故障対応が発生。
  「マニュアルを海外のクラウドに置くこと自体が不可」となった場合の代替案として保持。

## 推奨構成

### 案A: カード登録を一切しない（推奨）

```
利用者 → Cloudflare Pages(front) → Render(NestJS+FastAPI, シンガポール)
                                     ├─ Supabase(Postgres+pgvector, 東京)
                                     ├─ Backblaze B2(PDF, 米国)
                                     └─ Cloudflare Workers AI(回答・埋め込み・画像)
認証: Entra ID(会社のM365)   通知メール: Graph API   定期ping/バックアップ: GitHub Actions
```

月額 **0円**。カード登録 **0枚**。

### 案B: カード1枚を許容（体感は案Bが上）

案AのRender→**Cloud Run（東京）**、B2→**R2（APAC）**に差し替え。
コールドスタートが1分→数秒、PDFも国内並みの速さになる。
GoogleとCloudflareにカード登録が必要で、理論上は超過課金があり得る
（本規模なら実質$0。予算アラート設定で監視）。

### 「ほぼ同じ」にならない点（正直な妥協点）

| # | 変わる点 | 影響 | 緩和策 |
| --- | --- | --- | --- |
| 1 | **回答品質**: Claude Haiku 4.5 → Llama 3.3 70B | 日本語はやや不自然になる。検索(RRF)は不変なので「どのマニュアルか」の精度は落ちない | プロンプト調整。将来課金可能になったらANSWER_PROVIDER=bedrock/anthropicに戻すだけ |
| 2 | **朝イチの起動待ち約1分**（案Aのみ） | 最初の1人だけ | 営業時間中はGitHub Actionsで起こしておく |
| 3 | **PDF表示が+0.1〜0.2秒**（案Aのみ） | 軽微 | 案BならR2のAPAC配置で解消 |
| 4 | **データの保存先が海外になる**（PDF: 米国、DB: 東京だがSupabase社は米国企業） | 会社の判断が必要 | 「学習利用なし」は全採用サービスで規約確認済み。国内限定が必須なら案C(自社設置)へ |

新しいURL（`○○.pages.dev`）になる点も周知が必要（ブックマーク・ホーム画面追加のやり直し）。

## 移行手順の概要（作業量: 実装3〜5日 + 会社への依頼待ち）

1. **会社に確認**（先に着手。待ち時間が一番長い）
   - IT管理者へ: Entra IDアプリ登録 + Mail.Send同意の依頼
   - 会社判断: マニュアルPDFを海外リージョンに置いてよいか / カード1枚の可否（案A/B分岐）
2. **コード変更**（AWSと並行稼働で安全に進められる）
   - rag: `WorkersAiEmbedder` / `WorkersAiAnswerGenerator` を追加（Protocol実装を1つずつ）
   - backend: JWKS検証をEntra IDのissuerに差し替え、Graph送信クラス追加
   - frontend: 認証をMSALに差し替え
   - docker-compose環境でMinIO+ローカルPostgresのまま動作確認（テスト87件が守る）
3. **データ移行**（1日）
   - `pg_dump` → Supabaseへリストア → 検索インデックス確認（reindex）
   - `aws s3 sync` → B2/R2へ（416MB）
   - 再埋め込みスクリプト実行（既存の `reingest-all.ts` の埋め込み版。一晩）
4. **並行稼働 → 切り替え**（1週間）
   - 新環境で数日試験 → 利用者に新URL周知 → AWS側を `aws-stop.sh` で停止
5. **撤収**（クレジット枯渇前に）
   - 最終バックアップ（pg_dump・S3全量・設定）をGitHub私有リポジトリ+会社PCへ
   - `docs/deployment-plan.md` の撤収手順どおりAWSリソース削除

## リスク

- **無料枠の改悪は現実に起きる**（今回の調査だけでもHF Spaces有料化・Fly無料廃止・
  Oracle半減・Gemini削減を確認）。対策: 全部品がDocker+S3互換+標準Postgresなので
  同種の無料枠へ1日で引っ越せる形を保つ。年1回この文書の出典を見直す。
- **Supabaseの一時停止**: GitHub Actionsのpingで回避。万一停止しても
  データは1年保持され、復帰ボタンで戻る。
- **バックアップ**: 今のAWS Backupの代替として、GitHub Actionsで毎晩
  `pg_dump` をアーティファクト保存（90日）+ 月1回B2へ保存。
